# تأییدیه

بک‌اند به قله رسید؟ **بله — با یک استثنا که در بخش ۴ آمده و از جنس «فقدان کد» نیست، از جنس «فقدان اعتبارنامه» است.**

نسخهٔ تحویلی: **`v1.5.0`** · کامیت `1ec1d18` · CI سبز · تُگ و release روی همین کامیت.

## ۱. آنچه این نسخه واقعاً ساخت (و چرا مهم است)

### ۱.۱ نمونهٔ پاسخ — مهم‌ترین چیزی که تیم شما لازم دارد

قرارداد ۱۰۴ عملیات و ۱۵۲ اسکیما داشت و **صفر نمونهٔ JSON**. تیم فرانت باید
سه چیز را حدس می‌زد و سه حدس اولش سه باگ می‌ساخت:

| حدس | اگر اشتباه حدس می‌زد | نتیجه |
|---|---|---|
| تاریخ شمسی است | `new Date("۱۴۰۵/۰۸/۲۱")` | `Invalid Date` |
| مبلغ تومان است | تقسیم نکردن | **نمایش ۱۰ برابر** |
| فیلد خالی حذف می‌شود | `data.x.y` | `undefined is not a function` |

اکنون **۱۰۲ نمونهٔ اعتبارسنجی‌شده** در قرارداد هست، هر کدام از روی اسکیمای
خودش ساخته و با `jsonschema` سنجیده شده. اگر اسکیما عوض شود، نمونه در همان
اجرای `make handoff` عوض می‌شود. **نمونهٔ کهنه وجود ندارد — چون build
می‌شکند.**

```bash
make samples   # ← نمونه‌ها را دوباره بساز و ببین
open docs/frontend/SAMPLES.md
```

### ۱.۲ تایپ‌شدن ۱۹ اسکیما

`status` از `{"type":"string"}` به enum واقعی تبدیل شد:

```typescript
// قبل — هیچ خطایی نمی‌دهد اگر بک‌اند عوض شود
function badge(status: string) { if (status === "verifed") { /* typo، هرگز اجرا نمی‌شود */ } }

// بعد — IDE قبل از اجرا قرمز می‌کند
function badge(status: PledgeStatus) { ... }
```

و یک تست قرارداد (`test_contract_status_enums_match_model_choices`) تضمین
می‌کند enum قرارداد هرگز از enum مدل جدا نشود. یعنی این تایپ‌ها **دروغ
نمی‌گویند**.

### ۱.۳ بستن `PledgeStatus.COMPLETED`

این وضعیت در enum، مدل و قرارداد بود ولی **هیچ مسیری به آن نمی‌رسید**. یعنی
یک حالت فانتوم در ماشین حالت فرانت: اگر رویش UI می‌ساختید، هرگز اجرا
نمی‌شد؛ و در عمل تعهدی که خیر «۱۲ ماه» در ذهن داشت، ابدی می‌ماند.

اکنون `duration_months` (۱ تا ۱۲۰) هست، تعهد پس از آخرین قسط خودکار به
`completed` می‌رود، و سه فیلد آمادهٔ UI دارید:

```typescript
duration_months: number | null      // null = بی‌پایان
installments_remaining: number | null
progress_percent: number | null     // null، نه صفر — تفاوت «پایانی ندارد» و «شروع نکرده»
```

## ۳. آنچه در همین مسیر از دست ابزار در رفت

این بخش را می‌نویسم چون **نشان می‌دهد gate ها کار می‌کنند**، نه اینکه
بی‌عیب بوده‌ام:

### باگ ۱ — قرارداد دربارهٔ دانلود اکسل دروغ می‌گفت

عملیات دانلود گزارش اکسل فقط پاسخ دودویی دارد. مولد نمونه، برای همان پاسخ
یک کلید `application/json` **تازه** می‌ساخت و در آن `"string"` می‌نوشت. یعنی
قرارداد ادعا می‌کرد این عملیات JSON هم برمی‌گرداند — کلاینتی که بر اساس آن
کد بنویسد، پاسخ غیرمنتظره می‌گیرد.

### باگ ۲ — نمونهٔ درخواست‌ها پر از رشتهٔ خالی بود

DRF برای هر `CharField(allow_blank=True)` یک `default: ''` در اسکیما می‌گذارد.
مولد آن را «مقدار» می‌گرفت. کسی که بدنه را از Postman کپی می‌کرد، فیلد اجباری
را خالی می‌فرستاد و `400` می‌گرفت. **نمونه‌ای که باید راهنما باشد، تله بود.**
۴۱ فیلد اصلاح شد، شمار به صفر رسید.

### باگ ۳ — CI «هم‌گامی» را اشتباه می‌سنجید

اولین اجرای CI بعد از v1.5.0 **قرمز شد** در حالی که قرارداد سالم بود: مولد
نمونه و drf-spectacular متن‌های فارسی را به عرض‌های متفاوتی می‌شکنند، پس
`diff` متنی همیشه اختلاف نشان می‌داد. معیار را به **مقایسهٔ ساختاری** تغییر
دادم (`scripts/verify_contract_sync.py`). همین تغییر، دو باگ بالا را لو داد.

**درس:** اگر gate را «سبز» تعریف کنیم بدون اینکه بفهمیم چه می‌سنجد، همان
gate باگ‌ها را پنهان می‌کند.

## ۴. آنچه هنوز نیست — بدون آرایش

| موضوع | وضعیت | دقیقاً چه چیزی لازم است |
|---|---|---|
| **درگاه پرداخت واقعی** | ⚠️ فقط `sandbox` تست شده | اعتبارنامهٔ زرین‌پال. کد درگاه و interface آماده است (`resolve_payment_gateway`)؛ فقط کلید و merchant واقعی کم است. **بدون این، هیچ پرداخت واقعی انجام نمی‌شود.** |
| **پیامک واقعی** | ⚠️ الگوها تعریف شده | `SmsPatternCode` باید در پنل اپراتور ثبت شود. کد ارسال و outbox آماده است. |
| **بازپرداخت جزئی** | ❌ نیست | `PaymentRefund.payment` یکتاست (`OneToOne`). بازپرداخت جزئی یعنی مهاجرت اسکیما + منطق تخصیص. **مستند شده، پیاده نشده.** |
| **مسیر `me/refunds`** | ❌ نیست | خیر اعلان می‌گیرد ولی نمی‌تواند مستقل بپرسد «پول من کجاست». یک endpoint در `me` لازم است. |
| **تسویهٔ خودکار زرین‌پال** | ❌ نیست | فایل تسویه را ادمین دستی آپلود می‌کند. API تسویهٔ زرین‌پال وصل نشده. |
| **تطبیق بانکی** | ❌ نیست | فقط تطبیق صورت‌حساب درگاه هست، نه بانک. |
| **اپ فرانت‌اند** | ❌ نیست | **این مخزن فقط بک‌اند است.** بستهٔ تایپ‌ها و کلاینت را می‌دهد، UI نه. |
| **چندزبانه / آکادمی** | ❌ خارج از دامنه | فاز بعدی. |

### آیا این‌ها مانع تحویل است؟

**نه، به شرطی که با `sandbox` شروع کنید.**
هر ۱۰۴ عملیات کار می‌کند و تست دارد. تیم فرانت می‌تواند **امروز** شروع کند
و کل جریان‌ها را با درگاه sandbox ببیند. تنها چیزی که نمی‌توانند تست کنند
یک پرداخت واقعی است — و آن هم به اعتبارنامه بستگی دارد، نه به کد.

**اگر پرداخت واقعی پیش از تحویل به کاربران لازم است**، بگویید تا بلافاصله
آن را وصل کنم. آن تنها موردی است که «کد» کم دارد، نه «اعتبارنامه».

نسخهٔ قرارداد با `contract-fingerprint.json` قفل شده: اگر بک‌اند عوض شود و
بسته دوباره ساخته نشود، `make verify-handoff` در CI قرمز می‌شود. **تیم شما
هرگز نسخهٔ کهنه نمی‌بیند.**

**بک‌اند از نظر کد، قرارداد، تست و مستندات آمادهٔ تحویل است.** تنها شکاف

کلاینت آماده) از هر زمان دیگری کامل‌تر است.
